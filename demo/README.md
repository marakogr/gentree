# Synthetic demo project

`demo/project/` is a fully invented Russian family and `demo/project-en/` is the
same family in English. Both are used for the README screenshots and manual
tours. Each contains **20 people, 51 events, 31 relationships, 2 sources and 12
citations**. Every name, date and place is fictional; they are safe to commit,
screenshot and share.

The project is a normal Gentree folder: `manifest.json` plus JSONL collections
wrapped in the standard row envelope (`schema`, `id`, `createdAt`, `updatedAt`,
`data`). The app reads it exactly like a real project.

## A short demo tour

- **Biography search.** Open **Search** and type `хранитель`. The first hit is
  Андрей Волков's biography: "Хранитель семейного архива. Начал собирать
  фотографии и рассказы родных в 1990-х." Search `пропал` finds both the note
  about Николай Лебедев and his death record ("Пропал без вести").
- **Tree.** The home person is Андрей Волков. **Ancestors** shows four
  grandparents, **Descendants** shows two children and two grandchildren, and
  **Whole tree** places the rest of the family.
- **Kinship.** Open **Kinship**, choose Андрей Волков and Вера Волкова, and press
  **Find relationship**. The page shows `внучка`, the two-step path, the common
  ancestor and a diagram with alternative routes.
- **Timeline.** 49 dated events from 1889 to 2025 and two undated stories; the
  undated list is intentionally kept separate.
- **Map.** 49 events carry a confirmed point, so the Map tab groups the family
  around Казань, Москва, Санкт-Петербург and Брянская область. Points are
  synthetic city centres, not real addresses.
- **Data quality.** Death and burial are ordered after birth, marriages list
  the second spouse, and no event contradicts the person's lifespan.

## Regenerate

Both projects are generated by deterministic scripts:

```bash
node scripts/make-demo-project.mjs demo/project
node scripts/make-demo-project-en.mjs demo/project-en
```

The English generator runs the Russian one and translates every visible string,
so the structure stays identical. The generator owns every id and date, so equal
input always produces equal files. Edit `scripts/make-demo-project.mjs` to add
people or events, never the JSONL by hand.

## Screenshots

The README galleries are captured from the real UI:

```bash
npm --prefix desktop/ui run ux:build      # isolated UX app (first run is slow)
make ux-setup                             # tauri-driver + msedgedriver

$env:CAPTURE_SHORT_NAMES = "1"
node scripts/capture-demo-screenshots.mjs docs/screenshots

$env:CAPTURE_LANG = "en"
$env:CAPTURE_DEMO = "demo/project-en/d3e00000-0000-4000-8000-000000000002"
node scripts/capture-demo-screenshots.mjs docs/screenshots/en
```

The script copies the selected demo into the isolated
`com.gentree.desktop.ux` app data, launches the real binary through WebDriver
and writes screenshots under `desktop/ui/e2e/artifacts/demo-*` or the output
directory passed on the command line. It never opens the normal app data or a
real archive. `CAPTURE_LANG=en` also switches the UI language and the labels the
harness clicks.

Selected screenshots are committed under `docs/screenshots/` (Russian README)
and `docs/screenshots/en/` (English README). The capture script deliberately
does not screenshot the Settings screen: it reads the user's real config and may
show local paths.

## Recording

The README hero animations are recorded frame by frame from the real app, not
captured from the screen:

```powershell
npm --prefix desktop/ui run ux:build      # isolated UX app (first run is slow)
make ux-setup                             # tauri-driver + msedgedriver

# Only for the assistant part; the app reads this variable, never the repo.
$env:GENTREE_CHAT_API_KEY = "<provider key>"
make demo-gif
```

`node scripts/record-demo.mjs` starts on an empty isolated library, imports a
GEDCOM generated from `demo/project-en` (or `demo/project`) through the real
**Import** screen, then walks the tree, kinship, events, timeline, map, search
and chat. Every frame is a WebDriver screenshot of the window content, so no OS
cursor, taskbar or other window ends up in the clip. The script needs `ffmpeg`
(`choco install ffmpeg`) and, for a much smaller GIF, `gifsicle`
(`choco install gifsicle`); without gifsicle it falls back to one palette for the
whole clip. It stops at the first failed step and writes:

- `docs/assets/demo.gif` and `docs/assets/demo-ru.gif` — light theme, the ones
  the READMEs use;
- `docs/assets/demo-dark.gif` and `docs/assets/demo-ru-dark.gif` — the same
  clips in the dark theme;
- `desktop/ui/e2e/artifacts/demo-video/demo.mp4` — not committed; attach it to a
  release or upload it by hand.

`CAPTURE_LANG=en|ru` and `CAPTURE_THEME=light|dark` narrow the run,
`CAPTURE_KEEP_FRAMES=1` keeps the PNG frames, `CAPTURE_DEMO` overrides the demo
folder. The generated GEDCOM is written to `%PUBLIC%\GentreeDemo`, and the
imported project stays under the isolated `com.gentree.desktop.ux` app data.
The assistant part sends only this synthetic demo to the configured provider.

## The Romanov demo

`demo/romanov/` (Russian) and `demo/romanov-en/` (English) are a second demo
built from public historical data instead of an invented family: the last
imperial family, **17 people, 52 events, 28 relationships, 3 sources and 12
citations**, with a public-domain portrait for every person. Dates follow the
Gregorian calendar; where a day is unknown the event keeps a year or month
precision or a qualifier, and one undated family story stays in the undated
list.

```bash
node scripts/make-demo-project-romanov.mjs demo/romanov ru
node scripts/make-demo-project-romanov.mjs demo/romanov-en en
node scripts/fetch-romanov-portraits.mjs demo/romanov ru      # Wikimedia Commons
node scripts/fetch-romanov-portraits.mjs demo/romanov-en en
node scripts/capture-romanov-screenshots.mjs docs/screenshots/romanov
```

The portrait script keeps files it already downloaded, so a second run is
offline. Media files live under the checksum-sharded `media/<xx>/` folders the
app expects.

The screenshots in `docs/screenshots/romanov/` walk eight screens: projects
before and after the project appears, people, the ancestor tree, the kinship
path (Nicholas II and his sister Xenia), an event with custom fields and an
approximate year, the map, and the assistant with its confirmation card.

## Open it manually

For a manual tour, copy the project folder into the isolated review app data
(`%APPDATA%\com.gentree.desktop.ux\projects\` on Windows) and launch the UX
build, or copy it into the normal app data only on a machine without a real
archive. The app has no "open folder" command yet; the demo is meant for the
screenshot harness and contributors.
