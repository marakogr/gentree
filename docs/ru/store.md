# Публикация в Microsoft Store

Gentree публикуется и в Microsoft Store — как full-trust пакет MSIX. Магазин
подписывает загруженный пакет сам, поэтому для этого канала не нужен
сертификат подписи кода, а обновления ставит Магазин. Здесь описаны пакет,
сборка и то, что нужно Магазину до первой отправки.

Канал GitHub при этом никуда не исчезает: `make build` по-прежнему собирает
установщик NSIS (со встроенным автообновлением), а `make portable` — портативный
архив. См. [`releases.md`](releases.md).

## Идентичность

Значения ниже взяты из Центра партнеров: **Приложения и игры → Gentree →
Идентификация продукта**. Они публичны и зафиксированы в
`desktop/apps/desktop/msix/AppxManifest.xml`; все остальное в манифесте
производно от них.

| Поле | Значение |
| --- | --- |
| Package/Identity/Name | `marakogr.Gentree` |
| Package/Identity/Publisher | `CN=CCBFC6D1-565E-4E3F-8A41-E60352A1730E` |
| Package/Properties/PublisherDisplayName | `marakogr` |
| Package Family Name | `marakogr.Gentree_3w8vqcv266qa8` |
| Код продукта в Store | `9NC0PQH3JF6C` |

Пакет, у которого `Publisher` отличается хотя бы на один символ, отклоняется при
загрузке. Поэтому идентичность записана ровно в одном месте — в манифесте, — а
`scripts/package-msix.mjs` читает ее оттуда.

## Сборка пакета

```bash
make store        # неподписанный MSIX для Центра партнеров
make store-test   # тот же пакет, подписанный локальным тестовым сертификатом
```

Обе команды запускают `tauri build --no-bundle --features store`, а затем
`scripts/package-msix.mjs`, который

1. копирует исполняемый файл и ресурсы плиток в каталог разметки,
2. рисует `Wide310x150Logo.png` и `SplashScreen.png` из
   `desktop/apps/desktop/icons/icon.png` (они нужны MSIX, но Tauri их не
   создает),
3. записывает `AppxManifest.xml` с версией Магазина `0.7.0.0`,
4. упаковывает разметку через `makeappx.exe` и распаковывает обратно, проверяя,
   что ничего не потерялось.

Результат — `release-assets/store/marakogr.Gentree_<версия>.0_x64.msix`, около
11 МБ. Нужны Windows, PowerShell, Node.js и Windows SDK (`makeappx.exe` и
`signtool.exe` ставятся вместе с MSVC Build Tools). Переменные `MAKEAPPX` и
`SIGNTOOL` переопределяют найденный путь к инструментам.

## Чем сборка для Магазина отличается

Пакет компилируется с `--features store`, и эта фича — вся разница с
GitHub-сборкой:

- плагин автообновления не регистрируется вообще (`src/main.rs`), поэтому
  приложение не может заменить собственный пакет. Политика Магазина требует
  обновлять пакетные приложения через Магазин, а каталог
  `C:\Program Files\WindowsApps` доступен только на чтение;
- `update_status` возвращает `channel = "store"` и `configured = false`, а обе
  команды обновления отвечают `UPDATE_NOT_CONFIGURED`;
- **Настройки → Обновления** сообщают, что обновления поставляет Магазин, и
  скрывают кнопки проверки и установки вместо того, чтобы предлагать заведомо
  неработающие.

Все остальное — та же программа: тот же формат проектов, тот же идентификатор
Tauri, та же локальная модель хранения. Пакет full-trust
(`Windows.FullTrustApplication` + `rescap:runFullTrust`), поэтому диалоги файлов,
папки проектов на диске и провайдер чата работают как раньше.

Три следствия упаковки стоит знать заранее:

- **Данные приложения виртуализируются.** `%APPDATA%\Gentree` внутри пакета
  указывает на
  `%LOCALAPPDATA%\Packages\marakogr.Gentree_3w8vqcv266qa8\LocalCache\Roaming\Gentree`.
  Поэтому сборка из Магазина и сборка с GitHub держат разные настройки и разные
  поисковые индексы, но обе могут открывать одни и те же папки проектов (замок
  `.lock` в проекте по-прежнему допускает только одну из них).
- **Нет загрузчика WebView2.** `--no-bundle` не создает установщик, который мог
  бы его запустить, поэтому пакет рассчитывает на системную среду WebView2
  Evergreen. В Windows 11 и в актуальных обновлениях Windows 10 она уже есть; в
  карточке Магазина это указано в системных требованиях.
- **`bundle.targets` здесь не при чем.** Tauri ничего не упаковывает: разметка
  MSIX собирается из обычного release-исполняемого файла.

## Отправка

1. **Пакеты**: загрузите файл `.msix`. Он должен остаться неподписанным —
   Магазин подпишет его после сертификации. Самоподписанный пакет (`make
   store-test`) годится только для локальной установки и при загрузке будет
   отклонен.
2. **Свойства**: категория *Продуктивность*, три языка интерфейса (en, ru, uk),
   Windows 10 1809+ x64.
3. **Возрастной рейтинг**: анкета IARC.
4. **Политика конфиденциальности**: URL обязателен, и здесь он честный — проекты
   остаются на диске, единственный сетевой выход — провайдер чата, которого
   настраивает сам пользователь.
5. **Заметки для сертификации**: объясните `runFullTrust` (настольное
   приложение, открывающее собственные папки проектов пользователя) и
   `internetClient` (необязательный чат).
6. **Цены и доступность**: бесплатно, нужные рынки.

Первая сертификация идет дольше последующих; новый пакет для уже
опубликованного приложения обычно проходит за сутки.

## Обновления

Выпуск обновления — тот же сценарий с большей версией:

1. поднимите версию в `desktop/Cargo.toml`,
   `desktop/apps/desktop/tauri.conf.json` и `desktop/ui/package.json` (плюс
   запись в changelog),
2. `make store`,
3. загрузите новый `.msix` в Центр партнеров и отправьте.

Магазин ставит обновления автоматически; пользователь может отключить
автообновление, а отправка, помеченная как **обязательное обновление**,
устанавливается в любом случае. Версия пакета — это версия приложения плюс
`.0`: `0.7.0` уходит как `0.7.0.0` и должна строго возрастать.

CI собирает пакет по тегу или вручную: workflow **Store package** прогоняет
линтеры и тесты store-сборки, собирает MSIX, проверяет идентичность и то, что
файл не подписан, и выкладывает `gentree-store-x64` артефактом запуска вместе с
`SHA256SUMS-store-x64.txt`. К GitHub-релизу артефакт не прикрепляется:
неподписанный MSIX нельзя установить широкой публике, а публичный канал — это
карточка в Магазине.

## Локальная проверка пакета

```bash
make store-test
Add-AppxPackage -Path release-assets/store/marakogr.Gentree_0.7.0.0_x64.msix
```

Флаг `--dev-sign` создает одноразовый самоподписанный сертификат с издателем
Магазина в качестве субъекта, кладет его в хранилище `TrustedPeople` текущего
пользователя и подписывает пакет, чтобы Windows приняла установку. Боковая
загрузка (sideloading) должна быть разрешена (Параметры → Система → Для
разработчиков). После проверки уберите тестовую установку и сертификат:

```powershell
Get-AppxPackage marakogr.Gentree | Remove-AppxPackage
Get-ChildItem Cert:\CurrentUser\My | Where-Object FriendlyName -like 'Gentree MSIX*' | Remove-Item
```

Поскольку тестовый пакет несет идентичность Магазина, тестовая и магазинная
установки Gentree — это один и тот же пакет: установка одной заменяет другую.
